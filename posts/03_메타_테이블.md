## BATCH_JOB_INSTANCE

<img src="./imgs/img002.png">

- `JOB_INSTANCE_ID`
  - BATCH_JOB_INSTANCE 테이블의 PK

- `JOB_NAME`
  - 수행한 Batch Job Name

BATCH_JOB_INSTANCE 테이블은 Job Parameter에 따라 생성되는 테이블입니다.
> Job Parameter는 Spring Batch가 실행될때 외부에서 받을 수 있는 파라미터입니다

Job Parameter는 다음과 같이 구현할 수 있습니다.

```java
@Slf4j
@RequiredArgsConstructor
@Configuration
public class SimpleJobConfig {

    private final JobRepository jobRepository;
    private final PlatformTransactionManager transactionManager;

    @Bean
    public Job simpleJob(Step simpleStepWithJobParam) {
        return new JobBuilder("simpleJob", jobRepository)
                .start(simpleStepWithJobParam)
                .build();
    }
    
    @Bean
    @JobScope
    public Step simpleStepWithJobParam(@Value("#{jobParameters['requestDate']}") String requestDate) {
        return new StepBuilder("simpleStepWithJobParam", jobRepository)
                .tasklet((contribution, chunkContext) -> {
                    log.info("========================================");
                    log.info(">>>>> requestDate={}", requestDate);
                    log.info("========================================");
                    return RepeatStatus.FINISHED;
                }, transactionManager)
                .build();
    }
}
```

실행시 param으로 requestDate=yyyymmdd로 주면 다음과 같이 나오게 된다.

<img src="./imgs/img003.png">

이를 실행하고 나서 BATCH_JOB_INSTANCE을 다시 보면 다음과 같습니다.

<img src="./imgs/img004.png">

새로운 Job Instance가 추가되었습니다

만약 같은 파라미터로 다시 실행하면 어떻게 될까요?

그러면 JobInstanceAlreadyCompleteException과 함께 다음 메시지가 출력됩니다.

```
A job instance already exists and is complete for identifying parameters={JobParameter{name='requestDate', value=20260803, type=class java.lang.String, identifying=true}}.  If you want to run this job again, change the parameters.
```

그러면 다시 파라미터를 바꿔서 작동하면 어떻게 될까요?

<img src="./imgs/img005.png">

정상적으로 수행되었고, BATCH_JOB_INSTANCE 테이블에도 정상적으로 추가 생성되었습니다.

<img src="./imgs/img006.png">

즉, 동일한 Job의 Job Parameter가 달라지면 그때마다 BATCH_JOB_INSTANCE에 생성되며, 동일한 Job Parameter는 두개 이혅 존재할 수 없습니다.

## BATCH_JOB_EXECUTION

<img src="./imgs/img007.png">

JOB_EXECUTION 테이블을 보면 3개의 ROW가 있다.

JOB_EXECUTION와 JOB_INSTANCE는 부모-자식 관계입니다.  
JOB_EXECUTION은 자신의 부모 JOB_INSTACNE가 성공/실패했던 모든 내역을 갖고 있습니다.

```java
@Slf4j
@RequiredArgsConstructor
@Configuration
public class SimpleJobConfig {

  private final JobRepository jobRepository;
  private final PlatformTransactionManager transactionManager;

  @Bean
  public Job simpleJob(Step simpleStep1, Step simpleStepWithError) {
    return new JobBuilder("simpleJob", jobRepository)
            .start(simpleStepWithError)
            .next(simpleStep1)
            .build();
  }

  @Bean
  public Step simpleStep1() {
    return new StepBuilder("simpleStep1", jobRepository)
            .tasklet((contribution, chunkContext) -> {
              log.info("========================================");
              log.info(">>>>> Step1");
              log.info("========================================");
              return RepeatStatus.FINISHED;
            }, transactionManager)
            .build();
  }
    @Bean
    @JobScope
    public Step simpleStepWithError(@Value("#{jobParameters['requestDate']}") String requestDate) {
        return new StepBuilder("simpleStepWithError", jobRepository)
                .tasklet((contribution, chunkContext) -> {
                    throw new IllegalArgumentException("[SimpleJobConfig.simpleStepWithError] 에러발생");
                }, transactionManager)
                .build();
    }
}
```

위 코드를 실행시키면 Exception과 함께 Batch Job이 실패했음을 볼 수 있습니다.  
그러면 BATCH_JOB_EXECUTION 테이블은 어떻게 변할까요?

<img src="./imgs/img008.png">

4번의 STATUS가 FAILED로 표시되는 것을 볼 수 있습니다.  
그러면 이번에는 에러 코드를 정상적으로 돌리면 어떻게 변할까요?

<img src="./imgs/img009.png">

BATCH_JOB_EXECUTION의 JOB_INSTANCE_ID 컬럼을 보시면 같은 ID (4) 를 가진 2개의 ROW가 보입니다.  
첫번째 ROW는 FAILED 이지만, 2번째는 COMPLETED 입니다.

여기서 이상한점은 동일한 Job Parameter로 2번 실행했는데 같은 파라미터로 실행되었다는 에러가 발생하지 않았다는 점입니다.  
Spring Batch는 동일한 Job Parameter로 성공한 기록이 있을때만 재수행이 안된다는 것을 알 수 있습니다.
