# Spring Batch 메타테이블

Spring Batch는 배치 작업의 실행 상태 및 이력을 관리하기 위해 다음과 같은 메타테이블들을 사용합니다.

- `BATCH_JOB_INSTANCE`
- `BATCH_JOB_EXECUTION`
- `BATCH_JOB_EXECUTION_PARAMS`
- `BATCH_JOB_EXECUTION_CONTEXT`
- `BATCH_STEP_EXECUTION`
- `BATCH_STEP_EXECUTION_CONTEXT`

이제 각 메타 테이블들의 역할이 무엇인지, 어떤 데이터들을 담고 있는지 설명하겠습니다.

## BATCH_JOB_INSTANCE

<img src="./imgs/img002.png">

- `JOB_INSTANCE_ID`
  - BATCH_JOB_INSTANCE 테이블의 PK

- `JOB_NAME`
  - 수행한 Batch Job Name

BATCH_JOB_INSTANCE 테이블은 Job Name과 Job Parameter 조합에 따라 생성되는 테이블입니다.
> **Job Parameter**: Spring Batch가 실행될 때 외부에서 주입받아 사용할 수 있는 파라미터입니다.

Job Parameter는 다음과 같이 구현할 수 있습니다.

```java
@Slf4j
@RequiredArgsConstructor
@Configuration
public class SimpleJobConfig {

    private final JobRepository jobRepository;
    private final PlatformTransactionManager transactionManager;

    @Bean
    public Job simpleJob(Step simpleStepWithJobParam) {
        return new JobBuilder("simpleJob", jobRepository)
                .start(simpleStepWithJobParam)
                .build();
    }
    
    @Bean
    @JobScope
    public Step simpleStepWithJobParam(@Value("#{jobParameters['requestDate']}") String requestDate) {
        return new StepBuilder("simpleStepWithJobParam", jobRepository)
                .tasklet((contribution, chunkContext) -> {
                    log.info("========================================");
                    log.info(">>>>> requestDate={}", requestDate);
                    log.info("========================================");
                    return RepeatStatus.FINISHED;
                }, transactionManager)
                .build();
    }
}
```

실행 시 파라미터로 `requestDate=20260803`을 주면 다음과 같이 로그가 출력됩니다.

<img src="./imgs/img003.png">

이를 실행하고 나서 `BATCH_JOB_INSTANCE` 테이블을 조회해 보면 다음과 같습니다.

<img src="./imgs/img004.png">

새로운 Job Instance가 추가되었습니다.

만약 동일한 Job Name과 동일한 Job Parameter로 다시 실행하면 어떻게 될까요?

Spring Batch는 이미 성공(COMPLETED)한 동일 파라미터의 인스턴스를 재실행하지 않으므로 `JobInstanceAlreadyCompleteException`과 함께 다음 메시지가 출력됩니다.

```
A job instance already exists and is complete for identifying parameters={JobParameter{name='requestDate', value=20260803, type=class java.lang.String, identifying=true}}.  If you want to run this job again, change the parameters.
```

그렇다면 파라미터 값을 변경해서 다시 실행해 보겠습니다.

<img src="./imgs/img005.png">

정상적으로 수행되었고, `BATCH_JOB_INSTANCE` 테이블에도 새로운 행이 추가 생성되었습니다.

<img src="./imgs/img006.png">

즉, **동일한 Job의 Job Parameter가 달라지면 그때마다 새로운 `BATCH_JOB_INSTANCE`가 생성되며, 이미 성공한 동일한 Job Parameter 조합의 `BATCH_JOB_INSTANCE`는 중복 생성될 수 없습니다.**

## BATCH_JOB_EXECUTION

<img src="./imgs/img007.png">

`BATCH_JOB_EXECUTION` 테이블은 Job의 실행 시도(시도 횟수)마다 생성되는 기록 테이블입니다.

`BATCH_JOB_INSTANCE`와 `BATCH_JOB_EXECUTION`은 **부모-자식 관계**입니다.  
`BATCH_JOB_INSTANCE`가 하나의 작업 명세(Job Name + Parameter)라면, `BATCH_JOB_EXECUTION`은 그 작업을 실행했던 **모든 성공/실패 시도 내역(시도 단위)**을 저장합니다.

```java
@Slf4j
@RequiredArgsConstructor
@Configuration
public class SimpleJobConfig {

  private final JobRepository jobRepository;
  private final PlatformTransactionManager transactionManager;

  @Bean
  public Job simpleJob(Step simpleStep1, Step simpleStepWithError) {
    return new JobBuilder("simpleJob", jobRepository)
            .start(simpleStepWithError)
            .next(simpleStep1)
            .build();
  }

  @Bean
  public Step simpleStep1() {
    return new StepBuilder("simpleStep1", jobRepository)
            .tasklet((contribution, chunkContext) -> {
              log.info("========================================");
              log.info(">>>>> Step1");
              log.info("========================================");
              return RepeatStatus.FINISHED;
            }, transactionManager)
            .build();
  }

  @Bean
  @JobScope
  public Step simpleStepWithError(@Value("#{jobParameters['requestDate']}") String requestDate) {
      return new StepBuilder("simpleStepWithError", jobRepository)
              .tasklet((contribution, chunkContext) -> {
                  throw new IllegalArgumentException("[SimpleJobConfig.simpleStepWithError] 에러발생");
              }, transactionManager)
              .build();
  }
}
```

위 코드를 실행시키면 예외(Exception)가 발생하며 Batch Job이 실패합니다.  
이때 `BATCH_JOB_EXECUTION` 테이블은 어떻게 기록될까요?

<img src="./imgs/img008.png">

`STATUS` 컬럼이 `FAILED`로 표시되는 것을 볼 수 있습니다.  

그렇다면 이 상태에서 에러 원인을 조치하여 정상 코드로 수정한 뒤, **동일한 Job Parameter**로 다시 실행하면 어떻게 될까요?

<img src="./imgs/img009.png">

`BATCH_JOB_EXECUTION`의 `JOB_INSTANCE_ID` 컬럼을 보시면 같은 ID (예: 4)를 가진 2개의 ROW가 생성된 것을 볼 수 있습니다.  
첫 번째 ROW는 `FAILED`이지만, 두 번째 ROW는 `COMPLETED`입니다.

여기서 핵심 포인트는 **동일한 Job Parameter로 재실행했음에도 불구하고 이번에는 `JobInstanceAlreadyCompleteException` 예외가 발생하지 않았다는 점**입니다.

이유는 Spring Batch가 **성공(COMPLETED)한 기록이 있는 JobInstance에 대해서만 중복 실행을 금지**하기 때문입니다. 이전에 실행 실패(FAILED)한 JobInstance는 동일한 파라미터로 다시 실행하여 실패 지점부터 재시도(Retry/Restart)할 수 있도록 허용합니다.
